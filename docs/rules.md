# 规则说明

每条规则记三件事：怎么判、为什么能机械判、什么情况下会误报。

判断依据是 GB/T 15834—2011《标点符号用法》里可被正则表达的部分。判断类条文（该不该断句、该用哪个点号）没有实现。

## ZP001 中文里用半角标点

中文字与字之间出现半角 `, ; : ? ! ( ) .`，主张换成对应全角。判定要求相邻窗口里出现汉字，避免打进英文句子。

**会放过：**

- 前后都是 ASCII 字母或数字（`a,b`、`1,000`、`v1.0.2`、`3.14`）
- 半角括号内全是西文（`foo(bar)`、`docs/a.md(见说明)` 其中 `foo(bar)` 放过、`(见说明)` 会报）
- 化学式上下标按西文算（`(NaPO₃)₆`）
- Markdown 图片的 `!` 前缀

**可能误报：** 程序代码混排段落里，作者故意保留半角的情况。用 `--rule ZP001=warn` 降级，或 `<!-- zh-punct: off -->` 包住整段。

## ZP002 纯英文语境里用全角标点

整行没有汉字却出现全角标点。中文输入法忘了切，或者粘了别人的全角标点。整行只有标点（比如独占一行的 `”`）不算。

## ZP003 汉字与西文之间缺空格

`汉字ABC` / `123汉字` 主张插空格。默认关闭，因为「第3章」「共5人」这类写法在中文里本来就合法。

**建议：** 正文类文档开 `warn`，公文类文档保持关闭。

## ZP004 成对符号不闭合

`“” ‘ ’ （） 「」 『』 《》 〈〉 【】` 开合数量不等。按全文累计，跨行有效，跨代码块仍然计数。

**不判：** 半角括号（归 ZP001 管）。

## ZP005 标点连写

`，。、；：？！` 中任何一个连续出现。`……` 和 `——` 是合法的双写，不在此列。

## ZP006 省略号写法

`...`、`。。。`、单个 `…` 都主张改成 `……`（两个三点省略号，占两个汉字位）。

`。。。` 与 ZP005 的边界：三个以上句点当省略号处理，两个句点也按省略号报，因为中文里「。。」基本是误触。

## ZP007 破折号写法

`--` 主张改成 `——`。表格分隔行 `| --- |` 不受影响（三个连字符）。

## ZP009 标点落在行首

换行后行首出现 `，。、；：？！）》」』”’—` 等。前提是上一行非空且有汉字——单独一行的标点、或空行后的标点不算。

这是避头尾的粗查，只在硬换行的文本里有意义；按语义换行的散文会报得偏多。

## ZP010 数字区间用半角波浪线

`1~2` 主张改成 `1～2`（浪纹线 U+FF5E）。默认关闭，因为工程文档里 `2~3cm` 极常见。

## 参考文献行豁免

以 `[12]` 开头（含表格里的 `| [12] |`）的行，整行的 `, ; :` 不再按 ZP001 判，`...` 不再按 ZP006 判。GB/T 7714 规定作者之间用半角逗号、西文题名保留原文省略号，按中文规则判会全场误报。

代价：这类行里真实的全半角混用也会被放过。

## 控制注释

| 写法 | 作用域 |
|---|---|
| `<!-- zh-punct: off -->` … `<!-- zh-punct: on -->` | 区段 |
| `<!-- zh-punct: skip-line -->` | 当前行 |
